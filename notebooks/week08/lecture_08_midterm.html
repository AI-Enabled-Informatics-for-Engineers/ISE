Identity and Privacy — How It Works
What this app does vs. what Canvas does This app captures your name and RUID before the exam, embeds them in every export, and timestamps your session. Canvas independently records your NetID login, IP address, and submission timestamp. Neither alone is sufficient — both together form the audit record.

Three-layer identity system:

1. Canvas login (primary auth) — You must be logged into your Rutgers Canvas account to access and submit this assignment. Canvas logs your NetID, timestamp, IP, and browser fingerprint automatically. The instructor sees this in the submission record regardless of what the HTML file contains.

2. In-app RUID capture — Name, RUID, and NetID entered at exam start are embedded in your answer export. This cross-references your Canvas identity with a second identifier and includes a session timestamp.

3. Timestamped answer file (submission artifact) — After completing the exam you download a .txt file containing your identity, all answers, and a timestamp. Upload this file to Canvas. The Canvas submission log + answer file together form the complete grading record. Short answers are instructor-graded; MC is auto-scored in the app for immediate feedback.

Academic integrity: Submitting another student's file, or having another person complete the exam, violates Rutgers Academic Integrity Policy and is detectable through Canvas login records, writing-style analysis of short answers, and IP geolocation.

Week 8 Lecture

Chapter 4: Evaluate AI Systems

A model is only useful if it works for its intended purpose. Build the evaluation toolkit — from criteria definition through model selection to production monitoring.

Why Evaluation Comes First

Huyen opens with: which is worse — an app never deployed, or one deployed that nobody can measure? Answer: the deployed-but-unevaluable one. It costs to maintain, might be harmful, and is hard to take down.

Evaluation-Driven Development (EDD) — Define evaluation criteria before you build. Mirrors test-driven development in software. If you cannot measure success, you cannot claim it. Huyen argues evaluation is the single biggest bottleneck to AI adoption.

Why do measurable use cases dominate enterprise AI? Recommender systems: click-through rates. Fraud detection: dollars saved. Code generation: functional correctness. Un-measurable use cases stay un-deployed — not because they are less valuable, but because orgs cannot justify them.

The Four Evaluation Criteria Buckets

Bucket 1
Domain Capability
Can the model code, do math, parse legal text? Benchmarks: MMLU, HumanEval, BIRD-SQL. 75% of public benchmarks use MCQ format.
Bucket 2
Generation Capability
Factual consistency (local vs global), safety/toxicity, fluency, coherence. Key benchmarks: TruthfulQA, RealToxicityPrompts, BOLD.
Bucket 3
Instruction-Following
Does the model do what you asked? IFEval (25 auto-verifiable instruction types), INFOBench (content, style, linguistic constraints).
Bucket 4
Cost & Latency
Time to first token, time per token, total query time, cost per output token. Pareto optimization across quality-speed-cost.

Factual Consistency — Three Detection Approaches

Local: output vs. provided context (RAG, summarization). Global: output vs. open-world knowledge (general chatbots).

1
AI-as-Judge

Prompt an LLM to evaluate consistency. GPT-4 achieves 90-96% accuracy on TruthfulQA. Fast and flexible but subject to judge-model bias.

2
SelfCheckGPT

Generate N additional responses. If they disagree with R, R is likely hallucinated. Effective but expensive — N x cost per evaluation.

3
SAFE (Google DeepMind)

Decompose output into statements, make self-contained, query Google Search, verify each statement via AI. Scalable for global factual consistency.

Textual Entailment: formal framing of consistency as classification — Entailment / Contradiction / Neutral. Specialized models like DeBERTa-v3-mnli (184M params, 764K annotated pairs) beat general LLMs on speed and cost for this task.

4-Step Model Selection Workflow

1
Filter by Hard Attributes

License, data privacy policies, min throughput, on-device requirements. These cut the candidate pool before any testing — non-negotiable.

2
Shortlist via Public Benchmarks

MMLU, Chatbot Arena Elo, HumanEval, IFEval. Useful for relative ranking but treat with skepticism — leaderboard gaming is real.

3
Private Evaluation Pipeline

Your own prompt dataset, your own metrics. Ground truth for your application. Soft attributes (accuracy, toxicity) can be improved via prompting and finetuning.

4
Monitor in Production

Collect user feedback, detect distribution shift, watch for model update regressions. Re-evaluate model selection as scale and requirements change.

Open Source vs. Model API — 7 Axes

Self-Hosted / Open Source

  • Data never leaves your network
  • Full control — finetune, quantize, modify
  • Access to logprobs (eval + classification)
  • Predictable cost at scale; version freezing
  • Engineering burden: hosting, scaling, guardrails
  • Best open models trail best proprietary ones
  • License complexity (Llama 3, RAIL-M, Apache 2.0)

Commercial Model APIs

  • Best-performing models (GPT-4o, Claude 3.5, Gemini)
  • Scalability, function calling, structured outputs built-in
  • Fast to start, low upfront engineering cost
  • Vendor contracts can provide data lineage protection
  • Data leaves your org — privacy risk (Samsung/ChatGPT leak)
  • No logprob access; censorship guardrails limit some use cases
  • Cost scales linearly; model can change without notice
Rule of thumb: Start with APIs (low barrier, best models). Migrate to self-hosting when token costs exceed hosting cost + engineering burden. Re-evaluate quarterly as token volume changes.
